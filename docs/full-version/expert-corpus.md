# Формат экспертного набора для приёмки

Готовых реальных файлов у пользователя пока нет. Разработка продолжается на
учебных документах. Ни учебные данные, ни этот шаблон не подтверждают показатели
качества F01–F50. Реальная приёмка остаётся открытой.

## Организация набора

Одна папка соответствует одному тендеру. В ней находятся `case.json`, исходный
пакет заказчика, отдельные папки заявок и экспертная разметка. Оригиналы хранятся
в разрешённом закрытом хранилище, а не в Git. В репозиторий попадает только формат
разметки и явно учебные примеры. Для каждого оригинала фиксируются относительный
путь, SHA-256, язык и разрешение на обработку; имя файла не заменяет идентификатор.

Нужны 20–30 реальных тендеров: товары, работы и услуги, RU/UZ/EN, текстовые PDF,
сканы, фотографии, таблицы и чертежи. Тендеры разделяются целиком на development
и held_out: заявки, поправки и повторные копии одного тендера не попадают в разные
части набора. Разделение фиксируется до подбора промптов и порогов.

## Что размечает эксперт

- Атомарные требования, область товар/участник, позиция, важность, условия и
  источники. Для чисел — исходное значение, единица, оператор и допустимое
  округление; для сроков — дата, часовой пояс и правило на дату подачи.
- По каждой заявке — ровно один ожидаемый статус на каждое требование:
  `compliant`, `partial`, `unconfirmed`, `non_compliant` или `review`. Обоснование
  и точные цитаты берутся отдельно из пакета заказчика и этой заявки.
- Покрытие источников: какие страницы/области прочитаны, где отсутствуют сведения,
  а где документ не удалось прочитать. Отсутствие доказательств после полной
  проверки и недоступная для чтения область различаются.
- Для OCR — исходное изображение/страница, эталонная транскрипция, тип scan/photo,
  оригинальные координаты, числовые значения и явно нечитаемые области. Оценка
  CER использует зафиксированные правила нормализации; числа проверяются точно.
- Конкретные доработки, важность и применимость каждой рекомендации. Ожидаемый
  выигрыш рассчитывается по объединению затронутых требований без двойного счёта.

Цитаты сохраняются на исходном языке. PDF/изображения используют координаты
оригинала; DOCX — XML part/path и логические абзац/таблицу/ячейку; XLSX — лист и
адрес ячейки. Номер физической страницы DOCX/XLSX не выдумывается. Локальные ID
блоков полезны для сверки результата, но эталон также хранит независимый адрес
в оригинале, чтобы изменение версии парсера не меняло правильный ответ.

## Запись и проверка эталона

`expert-case.template.json` — незаполненный шаблон, не учебный правильный ответ.
`null` обозначает незаполненное поле. Перед включением случая в приёмку эксперт
заполняет все обязательные поля, проверяет SHA-256 и подтверждает цитаты в
оригиналах. `sources` может быть пустым только при обоснованном отсутствии
доказательств; подтверждённые положительные выводы требуют проверяемых источников.
Спорные пункты получают `review` и причину; их нельзя тихо исключать из отчёта.

Для held_out желательны независимая разметка и разрешение разногласий вторым
экспертом. Фиксируются версия разметки, эксперты, дата, замечания и решение.
Исправление эталона создаёт новую версию с причиной, сохраняя предыдущую.

## Отчёт приёмки

Каждый прогон фиксирует неизменяемые версии входов, разметки, парсеров, OCR,
моделей/промптов, политики скоринга, конфигурации и результатов. Отчёт показывает
числитель и знаменатель каждого показателя, распределение по языкам и типам
документов, ошибки и долю `review`, включая известные ограничения чтения.

Цели PRD: 100% recall обязательных требований, 100% точности известных статусов,
не более 15% `review`, ноль ложных зелёных обязательных пунктов, 100% проверяемых
источников; CER ≤2% для сканов ≥200 dpi и ≤5% для фотографий, точное совпадение
принятых чисел и применимость рекомендаций ≥80%. Отдельно проверяются полные
сценарии и время с очередью: 100 страниц ≤10 минут, 500 страниц ≤30 минут и
50 одновременных проверок на заявленном оборудовании с доступной квотой шлюза.

Эти цели не считаются выполненными до реального held_out прогона. Для учебных
прогонов отчёт обязан явно показывать `dataset_kind: synthetic`.
